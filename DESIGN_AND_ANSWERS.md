# Модуль 05. Домашнее задание (СРС): Клиентское приложение TaskManagerClient для управления задачами
## Архитектурные решения, реализация CRUD с HttpClient и ответы на контрольные вопросы

---

### Архитектурный разбор и организация клиент-серверного взаимодействия

#### 1. Роль и назначение TaskManagerClient
Приложение **`TaskManagerClient`** реализует клиентскую архитектуру управления задачами:
* **Представление (UI):** Интуитивный интерфейс на Bootstrap 5 с отображением статусов задач («Выполнено» / «В работе»), формами создания и редактирования.
* **Подтверждение удаления:** Для предотвращения случайной потери данных переход к удалению открывает специальное представление `Views/Tasks/Delete.cshtml`, где пользователь явно видит характеристики удаляемой задачи и подтверждает действие повторным нажатием кнопки.
* **Сервисный уровень:** `TaskApiService` инкапсулирует вызовы Web API через `IHttpClientFactory`, преобразуя HTTP-запросы и ответы в типизированные объекты `TaskItem`.

#### 2. Преимущества использования `IHttpClientFactory`
* **Исключение проблемы Socket Exhaustion:** Фабрика управляет пулом внутренних `HttpMessageHandler`, повторно используя открытые TCP-соединения и предотвращая накопление сокетов в состоянии `TIME_WAIT`.
* **Автоматическое обновление DNS:** В отличие от статического `HttpClient`, фабрика ротирует хэндлеры каждые 2 минуты, обеспечивая актуальность сетевых адресов.
* **Именованный клиент:** Имя `"TaskApi"` и базовый URL регистрируются централизованно в `Program.cs`:
  ```csharp
  builder.Services.AddHttpClient("TaskApi", client =>
  {
      client.BaseAddress = new Uri(builder.Configuration["ApiSettings:BaseAddress"] ?? "http://localhost:5000/");
      client.DefaultRequestHeaders.Add("Accept", "application/json");
  });
  ```

#### 3. Реализация CRUD-методов
* **`GET /api/tasks`:** Загружает полный перечень задач.
* **`GET /api/tasks/{id}`:** Загружает конкретную задачу по ID. При статусе 404 возвращает `null`, что обрабатывается контроллером как информационное предупреждение без падения приложения.
* **`POST /api/tasks`:** Создает задачу. При успехе (статус `201 Created`) возвращается созданный объект с присвоенным ID.
* **`PUT /api/tasks/{id}`:** Изменяет название, описание и статус выполнения (`IsCompleted`).
* **`DELETE /api/tasks/{id}`:** Удаляет задачу после явного подтверждения пользователем на странице `Delete.cshtml`.

#### 4. Обработка кодов состояния HTTP
* **`200 OK` / `201 Created`:** Успешное чтение, изменение или создание ресурса.
* **`400 Bad Request`:** Ошибка валидации данных. Текст ошибки возвращается и выводится в представлении.
* **`404 Not Found`:** Задача не найдена (например, была удалена другим пользователем). Выводится сообщение «Задача с указанным ID не найдена».
* **`500 Internal Server Error`:** Внутренняя ошибка сервиса. Ошибка перехватывается, логируется через `ILogger`, пользователю выдается дружелюбное сообщение.

### Ответы на контрольные вопросы

#### 1. Что такое `HttpClient` и каково его назначение?
`HttpClient` — это встроенный в .NET класс для отправки сетевых HTTP-запросов (GET, POST, PUT, DELETE) и асинхронного получения ответов от удаленных веб-серверов и REST API.

#### 2. В чем разница между `AddHttpClient` и созданием `new HttpClient()`?
* Создание `new HttpClient()` на каждый запрос приводит к исчерпанию доступных сокетов ОС (`Socket Exhaustion`), так как сокеты остаются висеть в состоянии `TIME_WAIT`.
* `AddHttpClient` использует пул `HttpMessageHandler`, переиспользует TCP-соединения, автоматически обновляет DNS-записи и полностью управляет жизненным циклом ресурсов.

#### 3. Как работает именованный клиент (`Named Client`)?
При вызове `builder.Services.AddHttpClient("TaskApi", ...)` регистрируется профиль настроек клиента с конкретным именем. В коде сервиса через внедрение `IHttpClientFactory` вызывается `factory.CreateClient("TaskApi")`, который возвращает преднастроенный экземпляр `HttpClient` с нужным `BaseAddress` и заголовками.

#### 4. Зачем в `appsettings.json` указывать `BaseAddress`?
Для выноса конфигурации внешней среды из скомпилированного кода. Это позволяет менять адрес целевого Web API при развертывании приложения в Docker, Kubernetes, на тестовом сервере или в облаке без необходимости пересборки проекта.

#### 5. Почему важно обрабатывать коды ответов (404, 500) и не ронять приложение?
Клиентское приложение работает в ненадежной сетевой среде. Сервер может временно упасть, вернуть ошибку или не найти удаленный ресурс. Падение приложения (Crash) ухудшает пользовательский опыт и может приводить к потере несохраненных данных. Грамотная обработка позволяет вывести понятное сообщение об ошибке и продолжить нормальную работу с системой.
